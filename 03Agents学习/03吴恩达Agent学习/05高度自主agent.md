# 高度自主agent
> 创建：2026.4.4

## 一、规划设计模式agent
### 1.Planning agent简介
  - 根据用户输入的任务信息，LLM拆解任务、生成行动计划、逐步执行行动计划，最终完成任务、生成对用户的回复；
  - 自主规划的智能体无需提前硬编码LLM执行复杂任务时的具体步骤顺序；
  - 规划设计让LLM和agent系统更难以控制，因为系统运行前，你不知道LLM会生成什么样的任务的行动计划。

### 2.LLM 创建和执行JSON格式行动计划
    如何提示LLM生成、阅读、理解并执行任务行动计划
    - system prompt要求LLM生成JSON格式的行动计划\
      ```
        你可以使用以下的工具：
        {可用工具清单描述}
        用JSON格式创建一个分步行动计划，每一步应该有以下内容：
        步骤序号、步骤描述、调用的工具名称和参数。
      ```
    - LLM生成一个JSON格式的分步行动计划；
    - LLM自主调用工具，分步执行行动计划；  

### 3.LLM创建和执行用代码生成的行动计划
  - System prompt编写
    ```
      编写代码回答用户的查询请求，用Python代码返回你的回答，代码格式用<execute-python></execute-python>标识
    ```
  - 让LLM编码代码生成任务行动计划，并分步执行。
  - agent完成复杂任务的效果：**编码生成行动计划>JSON格式的行动计划>文本格式的行动计划**。
  - 因为有些场景你希望LLM调用自定义的tools，所以编写代码生成行动计划并不适合所有场景。 

## 二、多智能体工作流
### 1.任务（有序子任务）vs工作流（有序工作部件）
- 任务可拆解成一组有序的子任务，生成任务行动计划；
- 工作流由一组有序的工作部件（component）组成；
- 工作部件（component）vs 子任务，工作流是任务行动计划的流程化体现；
- 工作流可以抽象、模块化、重用、解耦：
  - 使用一个agent实现工作流时，agent硬编码控制工作流，子任务（部件）由一个或多个LLM + tools实现；
  - 使用Multi_agents实现工作流时，顶层agent自主控制工作流，子任务（部件）由多个subagents实现，subagents内含LLM + tools；
- 总结：**子任务、工作流部件、tools、subagents是计算机面向对象的不同设计模式而已，抽象程度、设计思想、应用场景、模块划分有所差异而已，但本质是相同的**。 

### 2.多智能体通信模式
- 线性通信模式：多个智能体之间按工作流顺序执行的通信方式；
- 两层级通信模式：子智能体与顶层智能体进行通信，子智能体之间不通信；
- 多层级通信模式：由三层及以上智能体组成，子智能体与顶层智能体进行通信，子智能体与其下层的子智能体通信；
