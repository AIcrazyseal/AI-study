## 一、Reflection Design pattern
- 反思型agent并不是每次都能100%提升agent输出成果质量
- 有外部反馈信息输入时，反思型agent性能提升更好
- 反思型agent中，生成初稿的LLM和反思初稿的LLM，可以是同一个LLM（两个LLM client的Prompt是不一样的）；也可以是不同的两个LLM，**具有推理能力（又叫思考能力）的LLM在反思型agent中表现更好**
- 提升编写Prompt能力较好的方法是：多看别人编写的优秀Prompt；
- 相较于直接调用LLM、一次性生成结果，Reflectic Agent输出成果质量要好得多。

## 二、评估reflection agent
- 客观指标评估：可量化，逐一打分，根据总得分高低得出评估反馈意见。可通过编码实现评估。
- 主观指标评估：把主观描述拆分成更细的相对客观的指标，并逐一对细化指标打分，根据最终总得分高低得出评估反馈。
  - 用一个LLM生成初步成果，用另一个LLM评估初步成果质量，并反馈评估意见。这种评估结果并不好，而且LLM对评估Prompt的具体表述非常敏感，且存在位置偏见（即：如果Prompt给出多个选项，无论第一个选项是什么，LLM往往倾向第一个选项），需要不断优化Prompt提示词、调优reflectic agent
  - 不要用一个模糊的主观描述作为质量评估指标，应该把模糊的主观描述，拆分成几个更细的客观描述，且用逐项打分的办法评估更可行。例如：评估生成的一张图像的质量，Prompt不能说哪张图意思表达更清晰，prompt应该拆分出图像是否有标题、图像类型是否合适、有坐标轴描述和单位、图例是否有说明、图像数字是否容易理解等等。
  
## 三、使用外部反馈优化reflection
外部反馈远比LLM内部反馈对agent性能提升更好。
- agent生成的输出，在现实世界中执行并获得反馈，将反馈再次输入给agent，让其再次优化；例如agent输出程序代码，在电脑上运行后得到错误信息，将错误信息输入给agent，让其再次重新代码；
- agent生成输出后，让其调用tools，对基本常识问题进行联网搜索核实，对Prompt中提出的规则进行函数验证（例如不能出现竞争对手的名字、生成文本不能超过约定的字数限制等），agent调用tools执行后获得的反馈，输入到LLM中，让其重新修改输出成果。
