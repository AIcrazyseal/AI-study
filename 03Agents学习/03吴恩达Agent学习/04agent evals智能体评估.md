# Agent evals and error analysis智能体评估和错误分析
> 创建：2026.3.29

**能否推动有纪律的agent workflow 开发评估流程，是高、低效团队区别的关键**。\
**具备对Agent的评估和错误分析的能力，是非常关键的技能**。

## 一、Agent评估的工作流程
Agent工作流评估的规范程度，直接决定了Agent最终的工作效率和质量。\
Agent工作流评估原则：**快速搭建原型，观察系统表现，确定精力投入环节，持续改善**
- 1.Agent评估工作流程
  - 先构建粗糙的Agent工作流；因为构建Agent工作流之前难以提前预见问题，所以难以决定把精力重点投入到哪个环节。
  - 选择10-20个数据集测试Agent功能，观察并记录（用excel记录每个实测数据的agent输出、存在的问题）未达预期的地方（此处也可以创建agent质量测评方法）；
  - 建立agent质量评估方法，因业务功能不同、出错地方不同，评估方法也不同，以下是一个示例：
    - 评估方法一：
        - 在Prompt中规定LLM输出的格式；
        - 编码，从LLM response中按预定格式提取信息；
        - 比较LLM response与正确结果的差异，计算测试数据集的正确率。
    - 评估方法二：
        - 为每个topic选择3-5个核心讨论点；
        - 用LLM作为评估工具，统计agent生成的内容提及了多少讨论点；
        - 为每个评估集的Prompt打分；
  - 分析测试和评估发现的问题，有针对性的在此处投入精力，完善系统；
  - **持续迭代**：agent调优、评估体系调优。

- 2.评估体系构建要点
  - 评估体系构建原则：评估体系**要反应应用程序关注的地方、担心出错的地方**。
  - 关注agent表现不佳或出错的测试数据集，对提升agent效果非常有用。 
  - agent调整过程中，追踪每次调整得出的正确率变化情况，从而判断agent调整的成效。 
  - 初始10-20个数据集可以更换、扩大数据集规模。
  - 当你能明显感觉agent调优后效果提升显著，但评估结果却没有体现出得分更高，此时，需要收集更大的评估数据集，或者调整评估方式。

- 3.评估体系维度划分
  - 主观、客观评估维度
  - 每个样本是否有真实值(per-example ground truth)

## 二、评估方法
评估方法有端到端（End-to-End）整体评估、组件级（Componet-Level）局部评估两种。

- 1. 端到端（End-to-End）整体评估：可以衡量Agent整体输出成果的质量，流程复杂、耗时长、成本高；
  - agent表现效果不佳，可能是LLM提取搜索的关键词不当、搜索工具搜索质量低下、LLM选择和抓取搜索结果较差、LLM遗漏抓取内容的要点等；
  - agent trace（智能体轨迹）：agent和LLM所有中间步骤的输出集合；
  - agent和LLM span（跨度）：agent和LLM的单步输出结果；
  - 大模型轨迹追踪与错误分析：Examine traces to Perform error analysis,逐步分析agent和LLM每个中间输出结果，了解agent工作流每一步都在做什么，判断每一步表现优劣，再寻找改进机会；
    - 逐步分析agent和LLM的每个中间输出结果，就能初步判断agent最终的输出质量；
    - 建立错误分析统计表：表头每一列为agent全部组件或者重点组件名字，每一行对应一个测试数据集，每个单元格的内容为某个测试数据在某个组件运行时产生的中间结果评价或者错误信息（即输出结果明显低于人类专家知识）；
    - 计算错误分析统计表每一列的错误率，由高到低排序；agent调优环节的优先顺序由错误率高到低进行；
    - 错误分析能帮助我们选择努力的方向，极大提升agent调优效率；复杂系统中需要优化的环节很多，每个环节优化都需要花费大量的时间；

- 2. 组件级（Componet-Level）局部评估：可以评估Agent工作流程某一个步骤的输出成果质量。
  - 针对agent某个组件进行单独评估，评估结果指导agent调优；
  - agent工作流由多个组件组成，每个组件可以由专门的团队负责评估、调优，**各组件评估、调优可以同步、并行开展**；
  - 组件评估、调优完成后，应该再做端到端整体评估。

## 三、调优方法-解决实际发现的问题
- 1.non-LLM组件调优方法
  - 调整组件的参数，例如调整搜索组件的搜索结果数量、日期范围等参数；
  - 更换组件，寻找性能、效果更好的组件，替换现有组件。  

- 2.LLM组件调优方法  
  - 优化Prompts提示词，例如：Prompt更清晰、明确，提供少量样本，规定输出格式；
  - 使用不同的LLM，通过评估选取最合适当前任务的LLM；
  - 利用AI Suite或其他评估工具辅助调优；
  - 如果某一步骤对单一LLM来说太复杂，可以把任务拆解成更小的步骤，或者拆分为生成步骤和反思步骤；
    - 如果Prompts很复杂，单一LLM可能难以完全遵循这些指令；
    - 把任务拆分成更小的步骤，多次调用LLM分别完成更小的步骤，这样任务的准确率可能会更高。 
  - 如果其他方法效果不佳，可以试试微调LLM，此项行为最复杂、工作量最大、成本高。 

## 四、如何培养LLM选择直觉
  开发者要有对LLM的智能和能力的直觉，**高质量的Prompt + 合适的LLM = 高效的工作**。
  **小规模参数的LLM擅长回答简单事实性问题，前沿大规模参数的LLM遵循指令的能力远胜过小规模参数的LLM**；
  不同的LLM适合不同类型的任务，因为LLM训练的数据、参数权重是未知的，所以只能通过实践测试，才能猜测LLM更适合哪些类型的任务。
   - 经常试用不同的模型，包括闭源专有模型、开源权重模型，尝试不同类型的查询；
   - 建立一套个人对LLM的评测标准很有帮助：准备一套常用问题，向不同的模型提问可以帮助你评估LLM的表现、在不同任务上的实际效果；
   - 花时间阅读别人的Prompt（网上公开的prompt、开源包中的prompt、与行业大佬交流等），了解他人是如何最大化利用LLM的想法，这些行为有助于提升自己编写Prompt的能力，帮助你培养直觉，判断LLM擅长执行哪些类型的prompt，以及在何时对不同的LLM说什么样的话；
   - 在agent workflow中用不同的LLM，也可以帮助你培养直觉，了解哪些LLM更适合哪些类型的任务；
   - 通过查看LLM的执行轨迹获得对LLM正式的理解，或者通过 End-to-End、组件级评估判断不同LLM在workflow各个环节的表现，有助于培养对LLM性能的直觉、不同LLM在价格和速度上的权衡；
   - AI Suite可以让agent很轻松实现快速切换不同的LLM，这有助于高效测试和评估哪些LLM最适合我的workflow；

## 五、如何让agent workflow速度更快、成本更低
agent workflow优化顺序如下：
  - 先观测agent完成任务的质量是否达标、是否足够高；
  - agent投入实际生产环境且运行良好后，通常需要让系统运行的足够快、降低成本；
  - 工作流基准测试：计算工作流每一步骤的基准值（时间、成本）；
  - 优先优化占比最大的步骤。

### agent workflow延迟(速度)优化
- 工作流耗时基准测试：对工作流中的每一步进行计时；
- 统计agent workflow整体运行时长、每一步用时占比；
- 找出agent workflow用时占比最大的步骤，判断其延迟(速度)优化空间；
- 延迟(速度)优化措施：
  - 步骤并行处理：是否可以并行处理agent workflow中的某些步骤；
  - 更换参数更小的LLM：如果LLM处理耗时较长，用更小参数规模的LLM，看看生成效果是否足够好；或者替换为速度更快的LLM。

### agent workflow成本优化
- 工作流成本基准测试：计算工作流中每一步成本(token数量)；
- 统计工作流整体成本、每一步成本占比；
- 找出工作流中成本占比最多的步骤，判断其成本优化空间；
- 成本优化措施：
  - LLM按token数量计价，每个LLM提供商的token单价不一样；
  - API按调用次数计价，每个API提供商的单词调用价格不一样；
  - 不同的计算步骤成本取决于服务器容量付费方式和服务使用量；
  - 选择更便宜的LLM、组件。   

## 六、总结
- 构建agent：编写软件，进行错误分析，实现功能，完成任务；
- 分析评估agent：分析、追踪agent每一个步骤，用End-to-End或组件级方法评估其质量、耗时、成本等指标；
- 构建小型数据评测集，测试评估agent；
- 迭代：构建和分析评估agent相互循环，不断调整、优化agent直至达标；
- 利用通用工具：监控agent执行轨迹、记录运行日志、计算成本等工具，DeepMind.ai的short course partner提供了这些工具；
- 针对具体应用和遇到的问题，构建定制测评集。
